# Reference: Testcase RAG Impact

## Good user query patterns
- Include feature name and changed behavior.
- Mention target area (api, ui, quote flow, calc, validation).
- Mention intent (impact analysis vs full regression scope).

Examples:
- "Feature: ERL override for premium quote. Need impacted tests."
- "Build regression scope for sampling changes in policy issuance."

## Suggested compact answer style
Use:
1. `Summary` for high-level impact.
2. `Potentially impacted test cases` for concrete items.
3. `What to test first` for prioritization.
4. `Sources` to keep traceability.

Note:
- The retrieval script now returns context only.
- Final analysis is generated by Cursor chat model, grounded in the `Context for Cursor LLM` block.

## Retrieval tuning hints
- Default: `k=6`
- For broader discovery: `k=10`
- For focused follow-up: `k=3..5`

## Troubleshooting
- Missing API key: check `.env` has `OPENAI_API_KEY=...`
- Empty results: verify `chroma_db` exists and was populated.
- Noisy results: rewrite query with business terms and constraints.
